ILOVEKUSH — PACOTE COMPLETO V3

1. EXTRAIA o ZIP no computador.
2. ABRA a pasta extraída para ver seu conteúdo.
3. Na raiz do repositório no GitHub, abra Add file > Upload files.
4. No Explorador do Windows, selecione TODOS OS ARQUIVOS E TODAS AS PASTAS
   dentro da pasta extraída e ARRASTE esse conteúdo para a tela do GitHub.
   Escolher apenas os arquivos soltos deixa os fontes das pastas sem atualizar.
5. Confirme que a lista de upload inclui:
   index.html
   package.json
   release-manifest.json
   src/main.tsx
   src/styles.css
   public/versao.json
   scripts/check-release.mjs
   e os demais arquivos do pacote.
6. Clique em Commit changes na branch de produção.
7. Aguarde o novo deploy ficar Ready na Vercel e confira se ele corresponde
   ao commit desse upload. Redeploy de um deploy antigo pode usar o código antigo.
8. Acesse:
   https://pdf.kush-archives.com.br/versao.json?v=2026-10-27-v3
   Deve aparecer "versao": "2026-10-27-v3".
9. Abra a página inicial. O título deve permanecer "kush4rchives | ilovekush"
   após o carregamento. O cabeçalho contém apenas Portfólio/GitHub e o envio
   de arquivos fica dentro das ferramentas.

Os caminhos são importantes: os arquivos de src ficam dentro de src, os de
public dentro de public e os de scripts dentro de scripts. O conteúdo do ZIP
fica na raiz, sem uma pasta extra envolvendo o projeto inteiro.

O build verifica o manifesto antes de compilar. Se faltarem arquivos ou houver
fontes de versões diferentes, ele lista os caminhos que precisam ser enviados.
Isso facilita detectar um upload parcial antes de publicar uma interface antiga.

Para editar este projeto localmente: após alterações intencionais nos fontes,
execute npm run release:manifest e depois npm run build. Gerar o manifesto
reconhece os arquivos atuais como a nova entrega; não recupera arquivos ausentes.

O ZIP contém o projeto completo, sem credenciais, histórico Git, dependências
instaladas, caches ou builds gerados. A instalação e o build recriam os motores.
